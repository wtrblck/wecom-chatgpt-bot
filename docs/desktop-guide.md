# WeChatGPT 桌面工作台

本版本在 `wecom-chatgpt-bot-main` 中直接开发运行，不制作 EXE 或便携包。

## 启动

需要 Windows 10/11、Node.js 22+、Python 3.11+、PowerShell 7、.NET 10 SDK。首次安装运行 `npm run setup`，已有依赖时直接运行 `npm run desktop:dev`。开发启动会构建 TypeScript 与桌面 DLL，通过 `dotnet` 运行；不会自动启动机器人。

升级媒体依赖可运行：

```powershell
.\.venv-wechatdb\Scripts\python.exe -m pip install -r scripts/requirements-wechat-db.txt
```

本项目的 Node、Python 和 Chromium 依赖需要在本目录安装；另一个副本的登录和监听配置不会自动迁移。

## 第一次使用

1. 登录 Windows 微信，保持主窗口可用，并打开一个聊天窗口。
2. 在「监听会话」添加准确且唯一的群名或联系人名称；同名会话填写稳定微信 ID。只启用需要自动回复的会话。
3. 默认触发词为 `/gpt`、`@ChatBOT`、`@chatbot`，在触发词后加空格再提问。可自定义别名或关闭触发词限制。
4. 在「人物与指令」编辑人物设定和首次指令，或选用已保存模板。点击固定在页面底部的「保存全部设置」。
5. 在工作台检测环境，点击「登录 / 打开 GPT」，在专用浏览器完成登录，再启动机器人。

修改设置前先安全停止机器人和登录浏览器；保存后重启生效。有未保存修改时，启动按钮禁用。

## 人物设定、首次指令与模板

左侧的「人物设定」可填姓名、经历、性格、爱好和禁忌等内容。设置人物、语言风格、前后缀或补充要求后，点击「按左侧设定重建首次指令」。重建会覆盖右侧当前全文，重建后仍可直接修改。

右侧文本框是后端实际发送的完整首次指令，可直接编辑。内置「劳大（默认）」模板；点击「保存为新模板」可为当前全文命名，再点击页面底部的「保存全部设置」持久保存。以后从下拉列表选择并点击「使用所选模板」即可复用；默认模板不可删除，自定义模板可删除。

每个新 GPT 对话先单独发送已保存的首次指令，收到确认后再发送真正的问题；确认不转发到微信。监听会话自己的补充要求会在这条指令末尾追加。后续和重启后续聊复用已保存的对话，不重复初始化。

全部内容留空（包括会话补充要求）或关闭「启用回答风格」时，跳过初始化。关闭后，程序也不添加固定前后缀；原来的配置仍保留，重新打开开关即可继续使用。网页中的旧指令仍会影响旧对话，需新建 GPT 对话清除影响。

修改风格后，先保存并重启，再在「监听会话」选中目标点击「新建 GPT 对话」，也可发送 `/gpt /new` 或 `@chatbot /new`。仅重置所选会话的网页关联，不删除历史记录或影响其他群。网页指令用于引导语气，固定前后缀由程序在保存回答前补齐；已有时不重复添加，命令与错误提示不添加。

## 图片与表情（默认关闭）

「运行设置 → 解析本地图片 / 表情并上传给 ChatGPT」是显式开关，仅数据库读取模式支持。关闭时不加载媒体解析器、不扫描媒体缓存，也不上传从旧任务恢复的附件。普通群聊上下文可保留 `[图片]`、`[表情包]` 文字占位。

开启后的使用方式：

- 群聊：先发送图片或表情，再以 `@ChatBOT`、`@chatbot` 或你配置的 `@` 别名提问。最多附带最近 10 条尚未提交的上下文，图片与正文按「附件 1」等标记对应。
- 关闭触发词限制：已启用群聊或联系人的新图片、表情可以直接触发回答。保留触发词限制时，单独图片不会触发。
- 只处理微信已经保存在本机的媒体；不会访问表情中的 CDN 链接，也不会操作微信去下载原图。本地缺失、缓存被占用或解密失败时保留文字占位，不阻断普通文字任务。
- 支持常见 JPEG、PNG、WebP，以及可解码的微信 DAT。GIF、动态 WebP 表情上传第一帧。微信 WXGF/HEVC 图片需要本机 FFmpeg，缺失时无法转换的媒体使用占位。
- 每次最多 10 张，单张 20 MB、总计 100 MB，解码图像最多 4000 万像素。网页须显示全部附件预览、上传进度结束、发送按钮可用后才提交。上传失败或超时不会把缺图的问题当作正常提交。

导出的静态附件保存在 `data/wechat-db-cache/context-media`（自定义 `WECHAT_DB_WORKDIR` 时位于对应目录），用于排队恢复和 `/retry`。程序不自动清理仍可能被任务引用的附件；手动清理前先处理未完成任务。原始微信缓存不会被修改。

## 配置、记录与排障

桌面设置保存在 `data/desktop-settings.json`，校验后原子保存，优先于环境变量。指令模板和当前选择与其他设置一起保存。旧配置中的 `role` 会自动迁移为人物设定，原有分块风格仍可生成首次指令。环境变量使用 `REPLY_STYLE_ENABLED`、`REPLY_PERSONA`、`REPLY_LANGUAGE_STYLE`、`WECHAT_MEDIA_ENABLED`；旧的 `REPLY_ROLE` 仍兼容。

「运行记录」显示最近 200 条事件；完整机器人日志在 `latest.log`。日志不变时不重建列表，减少滚动跳动。诊断报告不包含群名、提示词或聊天记录。微信控件检测与登录检测是独立项；客户端最小化、版本变更或可访问性变化时，请还原微信并重新检测。

发送时仍核验目标和输入框，未知发送状态需先人工核对；不会自动重复发送。细节见 `docs/wechat-delivery-capabilities.md`。

## 离线验证

- `npm run check` / `npm test`：类型检查、配置/队列/恢复/上传边界测试。
- `npm run test:python`：合成微信数据库及本地媒体测试，需要 Python 依赖。
- `npm run chatgpt:upload:verify`：用本地 Chromium 页面测试真实上传等待逻辑，阻断所有网络请求。
- `npm run desktop:verify`：隐藏窗口渲染五个页面，不启动机器人、不访问微信或 ChatGPT，也不保存示例配置。截图与结果保存在 `.cache/desktop-smoke`。
